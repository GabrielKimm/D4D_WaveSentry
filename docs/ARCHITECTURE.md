# 운영 모드와 데이터 흐름

## RF 처리

```text
HackRF 수신 프로세스
  → 최신 완성 IQ 프레임
  → 전처리 작업 큐
  → OpenVINO / PyTorch 추론
  → 주파수·시간 판정
  → GUI, JSONL 기록, NU-87 경보
```

수신 프로세스는 최신 프레임 하나를 유지합니다. 전처리는 최대 두 작업만 진행하고, 추론은 순번이 증가하는 결과만 소비합니다. GUI 갱신과 USB 경보 통신은 별도로 처리합니다. 처리량이 수신량보다 낮으면 오래된 분석 프레임을 건너뛰며, 이 수치는 USB 손실과 구분합니다.

## 고정 대역 LIVE

| 항목 | 값 |
|---|---|
| 중심 주파수 | 2449.5 MHz |
| 판정 대상 | 2444.5–2454.5 MHz / 10 MHz |
| 수신 | 20 MS/s, signed int8 I/Q |
| IQ 프레임 | 20 ms / 400,000 complex samples |
| 모델 입력 | 640×640 grayscale, RGB 채널 반복 |
| 전처리 | Hann, FFT 8192, hop 4081, DC ±100 kHz 보정 |
| 기본 이득 | LNA 16 dB / VGA 16 dB |

전처리는 `vendor/iq_to_image.py`의 기준 구현을 사용합니다. 주파수 축은 위쪽이 높은 주파수이며 `fc + (0.5 − y/640) × 20 MHz`로 환산합니다.

drone 박스의 폭 7–13 MHz와 목표 주파수 IoU 0.60 이상을 후보 조건으로 사용합니다. 0.75초 안의 최근 3회 중 2회가 후보이면 확정하고, 마지막 후보 뒤 1.2초 유지합니다. 오래된 프레임과 새 USB 손실이 관측되면 판정을 보류합니다. 이 규칙은 특정 채널 관측을 위한 운영 조건입니다.

## 안테나 탐색 SURVEY

기본 관측 범위는 2400–2500 MHz와 5150–5890 MHz입니다. 전력·변화 후보와 대역별 순환 탐색을 함께 사용합니다. 같은 RF 영역의 근거는 시간 감쇠를 적용해 누산하며, 확정에는 독립적인 관측 회차가 필요합니다. 즉시 확인한 연속 프레임은 별도 회차로 늘리지 않습니다.

20 MHz 채널 가설은 중심을 ±6 MHz 옮긴 두 창에서 부분 근거를 확인합니다. 주파수 겹침, 시간 간격과 폭 조건이 맞는 근거만 합산합니다. IQ나 이미지를 이어 붙이지 않으며 동시 관측으로 취급하지 않습니다. 10 MHz 채널과 전체 1–6000 MHz·사용자 지정 범위도 설정할 수 있습니다.

오래된 근거, 대역별 관측 공백, 입력 품질 문제는 정상·후보·확정 상태와 구분해 표시합니다. 5 GHz·20 MHz의 일반화 성능은 별도 평가가 필요합니다.

## GUI와 데모

PySide6 작업영역은 스펙트럼, 모델 입력, 탐지 판정, 기록·로그 패널로 구성됩니다. `runtime/ui_layout.json`에 배치를 보존합니다. 실제 수신 중에는 모드와 RF 설정 변경을 잠급니다.

DEMO는 `DemoModel`의 합성 관측을 목록·지도·상세 패널이 공유합니다. 실제 수신 엔진이나 추론기를 생성하지 않습니다. 위성지도는 Qt WebEngine에서 동작하고, 정적 자원은 임의 포트의 `127.0.0.1` 서버로 제공합니다. 개략 지도는 네이티브 Qt로 렌더링합니다.

## 저장 및 상태

세션별 설정, 분석 결과와 요약을 `output/`에 저장합니다. 스냅샷은 요청 시 원본 IQ, 모델 입력 PNG와 판정 JSON을 함께 기록합니다. 통계 창 크기와 JSONL 파일 크기는 제한하지만 세션 누적 파일은 자동 삭제하지 않습니다.

NU-87 경보는 기존 판정 상태를 읽습니다. 후보나 원시 모델 점수만으로 경보를 승격하지 않습니다. 통신 지연·분리는 수신 스레드와 독립적으로 처리하며 최신 입력의 유효 시간을 검사합니다.
